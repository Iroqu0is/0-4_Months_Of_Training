# Большая итоговая работа (Сборная экосистема модулей)

Этот проект является итоговой демонстрацией моих навыков за первые **4 месяца изучения C# и .NET**. Он представляет собой единую консольную экосистему, где асинхронный ввод-вывод, многопоточность, кастомные структуры данных, рефлексия и сериализация работают в связке друг с другом.

## 🧱 Архитектура и структура модулей

### 1. Модели данных и ООП-контракты (`Person.cs`, `Employee.cs`)
Реализована иерархия классов с глубоким переопределением стандартного поведения .NET:
* **Наследование и полиморфизм:** Базовый класс `Person` расширен до `Employee` (Сотрудник компании).
* **Контракты сравнения:** Перегружены все операторы сравнения (`==`, `!=`, `<`, `>`, `<=`, `>=`), а также реализованы интерфейсы `IComparable`, `IEquatable` и `ICloneable`.
* **Защита от коллизий:** Метод `GetHashCode()` переопределен с использованием `HashCode.Combine` и приведения строк к одному регистру для корректного поиска сущностей в хэш-таблицах.
* **Фабричный метод:** Создание объектов изолировано внутри паттерна `Build`, который возвращает удобные кортежи с результатом сборки и текстом ошибки.

### 2. Продвинутые интерфейсы и обобщенная математика
* **Интерфейс `IUseless<T>`:** Использует фичу современных версий .NET — ограничение `where T : struct, IComparable<T>, INumber<T>`. Это гарантирует, что поле возраста (`Age`) может быть только системным числовым типом.
* **Интерфейс `IUnnecessary<T>`:** Строгий контракт для кастомных структур данных, реализующих поведение LIFO (Стек).

### 3. Кастомный стек `Pile<T>` (Потокобезопасное хранилище)
Собственная реализация стека на базе динамического массива:
* Инкапсулирует логику автоматического расширения внутреннего массива при достижении лимитов памяти.
* Защищен блокировками `ReaderWriterLockSlim` для стабильной параллельной работы.
* Помимо классических `Pop` и `Peek`, в класс встроены безопасные методы `TryPop` и `TryPeek` с `out`-параметрами для предотвращения падений.

### 4. Динамическая валидация через рефлексию (`InRange`)
* Создан кастомный атрибут `[InRange]`, принимающий типы `IComparable` для гибкой фиксации границ данных (например, возраста от 18 до 100 лет).
* Написан метод расширения `.InRange()`, который с помощью **Reflection (Рефлексии)** сканирует внутренности объектов, находит поля/свойства с атрибутом и на лету проверяет их валидность.

### 5. Асинхронный I/O и контроль параллелизма (`Program.cs`, `CancellationControl.cs`)
Вся логика завязана внутри асинхронного метода `Main`:
* **`CancellationControl`:** Самописный менеджер потоков. Он считывает количество ядер процессора текущей машины и динамически рассчитывает лимиты параллелизма (`MaxDegreeOfParallelism`) для TPL.
* **Асинхронный ввод-вывод:** Данные сотрудников сериализуются в JSON и параллельно записываются/читаются с диска с использованием `Task.WhenAll` и поддержкой токенов отмены (`CancellationToken`).

### 6. Потокобезопасный журнал `SimpleLogger`
Сервисный класс на базе `StringBuilder` и локов записи, который собирает сообщения об ошибках из параллельных потоков и выдает финальный отчет в блоке `finally` перед завершением программы.

## ⚠️ Исторические недочеты (Что осталось как есть)
Проект выложен в оригинальном учебном виде для демонстрации хронологии обучения:
* В фабричном методе `Employee.Build` присутствует избыточное двойное выделение памяти под базовый объект `Person`.
* Метод сжатия массива `Trim()` в стеке не имеет предохранителя от сжатия емкости до нуля.
* В методе `SimpleLogger.ThrowIfDisposed` из-за копирования кода осталась опечатка с именем чужого класса (`nameof(CancellationControl)`).
* Обработка фильтра исключений в `Main` содержит избыточное условие `when (true)`.
