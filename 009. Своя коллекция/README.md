# Потокобезопасная коллекция Salvatory<T>

Класс `Salvatory<T>` — это моя кастомная структура данных, написанная на базе динамического массива в рамках изучения C# и .NET. Проект создавался для того, чтобы на практике разобраться с многопоточностью, ручным управлением памятью и безопасным проектированием интерфейсов.

Коллекция реализует обновленный интерфейс `IRepositable<T>` (не ищите его, я сам его придумал :) и накладывает строгие ограничения на тип данных: `where T : IComparable<T>, IEquatable<T>`. Это гарантирует корректную работу встроенных алгоритмов поиска, сортировки и сравнения элементов.

## 🛠️ Особенности реализации

* **Раздельная потокобезопасность:** Доступ к элементам управляется с помощью `ReaderWriterLockSlim` (в режиме `LockRecursionPolicy.NoRecursion`). Чтение данных через индексатор или методы поиска происходит под `ReadLock`, что позволяет нескольким потокам читать данные одновременно. Модификация коллекции (добавление, удаление) строго изолируется под `WriteLock`.
* **Гибкая поддержка отмены (CancellationToken):** Методы линейного поиска (`TryFind`, `TryFindLast`, `FindAll`) и удаления поддерживают явную работу с токенами отмены. В целях оптимизации проверка токена выполняется раз в 10 000 итераций цикла. При этом в коде реализованы два разных подхода: метод `TryFind` генерирует системное исключение отмены, а метод `FindAll` мягко прерывает работу и возвращает `Array.Empty<T>()` без падения программы.
* **Освобождение системных ресурсов:** Поскольку класс использует системный синхронизатор `ReaderWriterLockSlim`, в коллекцию встроен паттерн `IDisposable`. При вызове `Dispose()` все системные локи корректно освобождаются, а повторные обращения к коллекции блокируются методом `ThrowIfDisposed`.

## 📜 Реализованный интерфейс IRepositable<T>

Коллекция поддерживает полный набор методов для управления данными, абстрагированный от конкретного класса реализации:
* **Индексатор `this[int index]`** для прямого доступа к ячейкам под защитой локов чтения.
* **Методы поиска:** Линейный поиск `TryFind`, поиск с конца `TryFindLast`, а также полная выборка элементов по условию `FindAll`. Служебные методы `IndexOf`, `LastIndexOf` и проверка наличия `Contains`.
* **Служебные методы:** Изменение емкости массива (`Resize`), сжатие до реального количества элементов (`Trim`), переворот (`Revers`), сортировка (`Sort`) и получение поддиапазона в виде чистого массива `GetRange(int index, int count)`.
* **Модификация:** Методы добавления (`Add`, `Join`) и удаления элементов (`Remove`, `RemoveAt`, `RemoveAll`, `Clear`).

## ⚠️ Исторические недочеты (Что осталось как есть)
Код коллекции сохранен в оригинальном учебном виде со всеми промежуточными недочетами. В частности, метод `RemoveAll` использует алгоритм со сдвигом элементов влево на каждой итерации, что дает вычислительную сложность O(N²) вместо оптимального метода двух указателей O(N). Также временный буфер в `FindAll` создает лишние аллокации в куче за счет создания внутренней коллекции. Это оставлено намеренно для фиксации истории обучения и эволюции кода.
